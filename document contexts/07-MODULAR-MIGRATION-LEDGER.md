## 2. Status Contract

| Status       | Meaning                                                                               |
| ------------ | ------------------------------------------------------------------------------------- |
| `unmapped`   | Current owner/behavior has not been classified                                        |
| `mapped`     | Initial responsibility, consumers, target, action, and evidence need are recorded     |
| `scaffolded` | Target manifest/extension/port path exists but current path remains active            |
| `wired`      | Target runtime uses the current or migrated implementation through an explicit bridge |
| `verified`   | Automated parity and required browser evidence pass for the vertical slice            |
| `retired`    | All consumers migrated; legacy path and temporary bridge removed                      |

No row may jump from `mapped` to `retired`. Source deletion requires `verified`
evidence and a fresh consumer-graph check.

Phase closure advances only rows whose ownership or compatibility path changed. An
unchanged `Keep` row may remain `mapped` even when module-level browser parity passes;
its future move/split still requires row-specific characterization. Target scaffold
files created after the 361-file Phase 00 snapshot are recorded by phase evidence and
the implementation commit rather than retroactively changing the baseline count.
